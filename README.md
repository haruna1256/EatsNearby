## アプリ名
EatsNearBy

### 動作対象OS
iOS 18
### 開発環境/言語
Xcode/swift
### 開発期間
8日間

### 機能概要
- レストラン検索	ホットペッパーグルメサーチAPIを使用し、ユーザーが指定した内容を元に現在地周辺の飲食店を検索する。
- 詳細情報取得	飲食店の名称、住所、営業時間、平均予算などの詳細情報を表示する。
- ホットペッパー連携	お店の情報をもとに予約サイトにすぐに確認できる。
- 地図アプリ連携	飲食店の所在地をMapKitに連携し、ルート検索が可能。
### 画面一覧
- 一覧画面 (TopPageView)	検索結果の飲食店を地図とリストで一覧表示するメイン画面。
- 詳細画面 (DetailPageView)	選択された飲食店の詳細情報（営業時間、予算など）を表示する画面。
- 検索画面 (SearchView)	検索条件（ジャンル、予算など）を指定・設定するモーダル画面。
### 使用しているAPI,SDK,ライブラリなど
- API: ホットペッパーグルメサーチAPI 
- SDK: MapKit (地図表示、ルート検索)
- 言語/フレームワーク: Swift / SwiftUI (UI構築), Combine または Swift Concurrency (async/await) (非同期処理)

## コンセプト
「迷ったとき、今すぐ使える地図連携型グルメアプリ」

地図とリストが一体化した画面で、ユーザーの「今いる場所」と「行きたいお店」を繋ぐことを目的としました。煩雑なメニューや複雑な検索条件を排除し、「見て、選んで、すぐ行動」できる直感的な操作を最優先に設計しました。

## こだわったポイント
### デザイン面でこだわったポイント
- 地図とリストの統合表示
  - 画面を上下二分割し、上部に地図、下部にスクロール可能なリストを配置。地図上のピンとリストの店舗を連動させることで、現在地からの距離と店舗情報を同時に把握できるようにしました。
- アクセントカラーの統一
  - 主要な要素（ルート検索、予約、重要情報）にaccentColorを使用し、ユーザーが次に取るべき行動が明確になるよう設計しました。
- テーマカラーと背景
  - ご飯のイメージになるように柔らかめのカラーとご飯のアイコンを背景に配置しました。
### 機能面でこだわったポイント
- ルート検索
  - リストや詳細画面からタップ一つで現在地を起点としたルートを計算し、即座にマップに表示する機能を実装。店舗探しから移動開始までの手間を最小限に抑えました。
- 状態管理の明確化
  - 位置情報の取得中、API検索中、エラー時など、アプリの状態に応じてユーザーに適切なフィードバック（ProgressView、エラーメッセージ）をリスト領域に表示するようにしました。
## 技術面でアドバイスして欲しいポイント
- 非同期処理の安全性
  - ホットペッパーAPIへのアクセスや位置情報取得における async/await または Combine のエラーハンドリングやキャンセル処理が適切かどうか。
- トップ画面に表示する内容の種類
  - 表示する内容の量が現状のもので最適かどうか
- apiからとってくる時のmodelの中身（いらないコード、書いたほうがいいコード）
- header,footerをかく場所
- マップの最適な表示の処理
  - 店舗数が多くなった場合の MapAnnotation の描画負荷軽減（例: クラスタリング機能の導入など）に関するアドバイス。
- 読み込み中の処理
